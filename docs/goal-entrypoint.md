# Handsel: 요청에서 실행 가능한 오피스로

2026-09-09 · 제품 설계 제안. 아래 진입 화면·자동 도구 선택·Higgsfield 어댑터는 아직 구현하지 않았다.

## 문제와 제품 약속

사용자가 고민하는 것은 모델 이름만이 아니다. 어떤 도구가 필요한지, 자기 계정에서
실행 가능한지, 파일을 어떻게 넘기는지, 실패한 단계를 어디서 재개하는지까지
사용자가 통합 담당자가 되고 있다. Handsel의 진입점을 이 비용을 줄이는 데 둔다.

제안 문장: **원하는 결과를 말하면, 지금 쓸 수 있는 AI와 도구를 묶어 끝까지 진행합니다.**
오피스는 사용자가 시작 전에 만들어야 할 조직이 아니라, 성공한 실행 방식과 고객별
기준을 저장하고 반복 운영하는 단위다. 한 번 맡기기 → 같은 방식으로 다시 하기 →
내 오피스로 저장하기 → 다른 고객에게 판매하기 순서로 깊어진다.

## 첫 화면과 흐름

현재 `/start`의 requester/worker 선택과 `/connect`의 클라이언트 연결 안내 위에
새 입구를 하나 더 추가하지 않는다. `/start`를 결과 요청의 기본 입구로 정리하고,
기존 연결·오피스 설정은 계획에서 필요할 때 이어지는 경로로 재사용한다.

- 중심 입력: 무엇을 끝내고 싶나요? 파일/링크와 납품 형식을 함께 받는다.
- 초기 예시는 결과 중심: 검수된 조사, 저장소 변경, 기존 3D 자산의 렌더/웹 변환.
- 첫 질문은 결과를 바꾸는 누락만: 편집 가능한 3D 원본도 필요한가? 외부에 보낼 수 있는가?
- 계획 카드에는 납품물, 사용할 연결, 대략적 비용(미확인이면 미확인), 승인 지점,
  빠진 연결만 보인다. 모델 목록과 직원 채용 화면은 고급 설정으로 둔다.
- 실행 후 작업별 진행/중단 사유/산출물/검수 결과를 한 화면에 모은다.
- 잘 된 설정을 오피스로 저장하면 다음 주문은 파일과 변경 사항만 받는다.
- 3D 오피스는 같은 세션의 선택적 시각화다. 진행을 확인하려고 공간을 돌아다닐 필요는 없다.

## 선택은 세 단계로 나눈다

1. 자격 필터: 제공되는 도구, 현재 인증, 입력/출력 형식, 로컬 실행 가능성, 개인정보
   정책, 허용된 유료 작업, 예산·시간 한도. 불가/미확인은 성공 확률과 별도로 보관한다.
2. 적합한 절차 선택: 검증한 소수 레시피에서 시작. 요청과 입력 파일에 맞춰 단계·검수를
   선택한다. LLM은 구조화 계획을 제안하지만 실행 권한을 부여하지 않는다.
3. 실행자 선택: 단계별 도구/모델/worker를 고른다. 모델 버전·입력 난도·검수 방식이
   비슷한 실행 이력이 충분할 때만 성과를 비교한다. 없는 실적은 추정 95%로 채우지 않는다.

단순 정리에는 가벼운 모델, 복잡한 계획/코드 수정에는 해당 능력이 검증된 모델,
파일 검사에는 결정적 도구, 이미지 판단에는 시각 입력 가능한 검수기를 쓴다는 것은
초기 정책이다. 특정 모델이 항상 최고라는 주장은 하지 않는다. 런타임에 제공자
카탈로그·가격·스키마를 확인하고 계획에는 선택 시점의 버전을 기록한다.

기대 비용은 호출 단가만이 아니라 재시도·렌더·검수·사람의 수정까지 포함한다.
권한 밖 모델/서비스로 자동 폴백하지 않는다. 비동기 생성 요청이 타임아웃되면 기존
job ID를 조회하며 재생성하지 않는다. 재시도 예산과 원래 승인은 함께 검증한다.

## 재사용과 필요한 구현

| 기존 자산 | 재사용 | 추가할 부분 |
|---|---|---|
| verified-connectors / MCP probe | 연결 및 인자 검사 | 사용자별 연결 상태, 검사 시각, 인증 만료 |
| claim-fitness / capability | worker 생존·작업 자격 | 입력/출력 스키마·로컬 파일/장치 능력 |
| tool-record | 실적·표본·서로 다른 계정 수 | 과제 유형/모델 버전/워크플로 버전별 관찰 |
| delegation / session | DAG·재시도·체크포인트 | 결과 요청을 재사용 레시피로 변환 |
| approval-policy | 비용/작업 승인 경계 | 외부 업로드·유료 생성·폴백 범위 표시 |
| artifact / proof | 파일과 판정 출처 | manifest·모델/도구 버전·부분 납품·고객 수락 |
| office / memory | 재사용 가능한 조직과 기준 | 성공한 실행을 오피스로 저장하는 UX |

등록됨, 핸드셰이크 성공, 시험 작업 성공, 운영 작업 성공은 네 가지 서로 다른 증거다.
Codex의 플러그인과 Handsel 서버의 인증·도구 접근은 공유되지 않는다. 도구 카탈로그의
설명이나 외부 문서를 실행 권한으로 해석하지 않는다.

OpenRouter는 모델 자동 선택과 failover를 이미 제공한다. 따라서 모델 선택만으로
차별화됐다고 주장하지 않는다. Handsel에서 시험할 차이는 사용자별 도구 연결부터
파일 전달·장기 실행·검수·반복 주문까지 유지되는 실행 방식이다.
참고: https://openrouter.ai/docs/guides/routing/routers/auto-router

## Higgsfield + Blender: 조합은 출력 요구에 따라 달라진다

| 요청 | 실행 경로 제안 | 검수와 한계 |
|---|---|---|
| 3D 오피스의 방·직원 시각 디자인 | Higgsfield 콘셉트 → Blender 모델/재질 → GLB → 기존 Three.js | 외형이 실제 상태/경로를 가리지 않는지 확인. 콘셉트 이미지가 3D 원본으로 자동 변환되는 것은 아님 |
| 제품/부품의 각도·색상별 미디어 묶음 | 고객 모델 → Blender 카메라·재질 변형/렌더 → 필요시 Higgsfield 배경·영상 | 형상/로고/색상을 유지해야 하는 컷은 Blender 원본 렌더 우선. 생성 영상의 형태 왜곡을 별도 검수 |
| 웹용 인터랙티브 전시 자산 | Blender 편집 원본+경량 GLB → 웹 미리보기, Higgsfield는 콘셉트/썸네일 | 텍스처 누락·용량·폴리곤·웹 로딩 검사. 실제 웹 배포는 별도 승인 |
| 설명/교육용 장면 패키지 | Blender로 구조·부품·카메라를 고정 → 렌더 → Higgsfield 보조 영상/음성 | 기술적 정확성은 원본·검사 기준으로, 미감은 고객 승인으로 |

모델 없이 이미지 한 장만 있고 형상 정확성도 요구하지 않으면 Higgsfield 단독 경로가
더 적합할 수 있다. 편집 가능한 원본·정확한 다각도·반복 변형이 필요하면 Blender
경로를 제안한다. 조합 자체가 목표가 아니라 필요한 결과가 선택 기준이다.

현재 로컬 Blender 5.2.1 LTS의 Python/GLB exporter 실행은 확인했다. Higgsfield 계정
조회도 성공했지만 Handsel 어댑터와 유료 생성/렌더 성능은 검증하지 않았다.
Higgsfield 3D Jutsu는 원격 프로젝트이고 로컬 Blender와 같은 세션이 아니다.
필요한 연결: 승인된 업로드 → 생성 job ID 저장/폴링 → 결과 다운로드 → 로컬 manifest
→ Blender worker → 기술 검사 → 시각 검수. 결과 원본·생성본·수정본을 구별해 저장한다.

## 초기 고객과 2주 실험

첫 후보는 이미 모델/도구 3개 이상을 오가며 반복 납품하는 1~5인 제작자·에이전시다.
AI를 처음 보는 모든 사람을 대상으로 시작하지 않는다. 첫 주에는 5명에게 각자 최근
반복 작업 두 가지를 가져오게 하고, 선택/로그인/파일 이동/재시도 시간을 실제로 잰다.
검증한 소수 경로를 사람이 감독해 실행해도 된다. 자동 라우터의 효과로 포장하지 않는다.

둘째 주에는 같은 사람이 같은 형식의 두 번째 작업을 수행한다. 성공 기준 제안:
5명 중 3명이 도구를 직접 고르지 않고 수락 가능한 산출물 도달, 시작 준비 시간이
자기 기존 방식보다 절반 이하, 2명이 같은 오피스를 다시 사용, 최소 1명이 정해진
유료 반복 사용에 결제. 품질·실제 비용·재작업은 기존 방식보다 악화되지 않아야 한다.
원치 않은 외부 전송·한도 초과는 없어야 한다. 비교 표본이 작으므로 시장 검증으로 일반화하지 않는다.

중단 기준: 추천은 좋아하지만 결국 사용자가 매번 도구에 직접 들어가거나, 설정 부담을
숨겼을 뿐 실제 작업 시간이 줄지 않거나, 수락 가능한 결과를 내려면 기존보다 비싸고
수정도 많아지는 경우. 모델/플러그인 수를 늘리기 전에 한 경로를 수정한다.

## 수익 구조 가설

처음에는 연결·실행 이력·반복 오피스 운영에 대한 구독, 외부 생성 비용은 분리 고지한다.
구독료는 고객의 기존 도구 이동·검수 비용을 측정한 뒤 시험한다. 검증된 오피스가
다른 사람의 작업을 수행할 때 외부 주문 수수료가 추가된다. 내부 도구 호출마다
회사 간 거래나 금융을 강요하지 않는다. 선지급은 외부 수주가 실제 자금 부족으로
막히는 관찰이 생긴 뒤에 별도로 검증한다.
